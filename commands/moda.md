Route the user's request to the right Moda skill and follow it. A skill whose
name has three segments is a recipe leaf: load it instead of its parent when the
request names its subject.

- A deck, slides, presentation, pitch, QBR, board update, "turn this into
  slides" → the **moda-deck** skill. An existing `.pptx` in hand →
  **moda-deck-pptx**.
- A one-pager, PDF, report (single OR multi-page), whitepaper, infographic,
  brief, handout, newsletter, "make this look designed" → the **moda-document**
  skill. Print pieces — poster, flyer, brochure, menu, resume, certificate,
  invitation, business card, merch → **moda-document-print**.
- A social post, carousel, story, quote card, profile header, logo/icon design,
  or "a simple graphic of X" → the **moda-social** skill (stills only — the
  animated version of any of these is moda-video). Platform named? Use the
  child: **moda-social-instagram**, **-linkedin**, **-tiktok**, **-youtube** —
  except an AD, which outranks the platform noun: static ads and banner sets,
  platform-native included ("an Instagram ad") → **moda-social-ads**.
- A video, GIF, animated ad or post, motion graphic, "make a video", animating
  a logo/image/design → the **moda-video** skill (it owns anything delivered as
  mp4/gif; still formats stay with moda-social). Generated clips —
  prompt-to-video, image-to-video, extend, upscale, reframe →
  **moda-video-clip**; motion authored on a canvas, stingers, timeline cuts,
  photo slideshows, mp4/gif export → **moda-video-motion**.
- A diagram, flowchart, org/architecture chart, decision tree, swimlane, 2x2
  matrix or market map → the **moda-diagram** skill.
- A standalone data chart from real numbers — bar, line, area, pie, scatter,
  combo → the **moda-chart** skill (a chart destined for a deck, document, or
  diagram being built stays with that skill).
- A UI mockup, wireframe, app screen, or page-design concept → the
  **moda-mockup** skill (a picture of an interface; a live hosted page is
  moda-website).
- A website, landing page, marketing site, portfolio, "put this on the web",
  or an existing moda.page site to change → the **moda-website** skill (a
  printable/PDF page stays with moda-document).
- An image as the deliverable — generate, edit, upscale a photo, remove a
  background, outpaint/uncrop → the **moda-image** skill (imagery inside a
  design you are building is generated by that format skill).
- Voiceover, narration, "read this aloud", music, a jingle, or sound effects →
  the **moda-audio** skill.
- Brand kits — list/show/create a kit, "use our brand", "match our site",
  audit a canvas against the brand → the **moda-brand** skill.
- A moda.app canvas URL / share link / `cvs_` id plus a change, export, or
  share request → the **moda-edit** skill.
- Workspace and files — upload, search team assets or stock, read an uploaded
  document, browse folders, find a canvas → the **moda-library** skill.
- Team templates — "use our template", "our usual QBR format", "what templates
  do we have", flagging a canvas as a template → the **moda-templates** skill,
  then the matching artifact skill.
- Pinning this repo's Moda defaults (org, brand kit, canvas) → the
  **moda-context** skill.
- Recurring work — "every Monday", "auto-post X", "keep this updated" → the
  **moda-automate** skill for the schedule; the artifact it produces each cycle
  still routes to its format skill.
- Installing or updating Moda, auth and org/team questions, "what can Moda do",
  which-skill routing, a failed Moda call → the **moda-core** skill (meta only;
  it never does the design work itself).

If the request spans several (e.g. "an on-brand deck"), the artifact skill
leads (moda-deck) and pulls brand data per its references. If none fit, load
**moda-core** — it owns the tie-breaks and the none-fit case.
